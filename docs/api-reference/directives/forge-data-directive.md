# ForgeDataDirective - Référence Technique

## Description

Crée une nouvelle classe Data DTO (Data Transfer Object) dans le projet. Cette directive génère automatiquement un fichier PHP avec la structure de base d'un Data DTO, en utilisant les tags personnalisés pour enrichir la documentation.

## Hiérarchie / Implémentations

```
AbstractDirective
    └── ForgeDataDirective
```

**Interfaces implémentées :** `DirectiveInterface`

## Rôle principal

`ForgeDataDirective` est une directive de génération de code qui crée des classes Data DTO (AbstractData) dans le dossier `app/Datas/` ou `src/Datas/` selon la configuration du projet. Elle :

- Analyse le nom fourni pour déterminer le namespace et le nom de la classe
- Gère les sous-dossiers via la syntaxe pointée (ex: `admin.user` → `Admin/UserData.php`)
- Supporte les tags personnalisés pour enrichir la documentation
- Vérifie l'existence des fichiers avant de les créer
- Génère un stub avec les imports et la structure de base

## Installation

Le package `directive-forge` est requis. La directive est automatiquement disponible après installation.

```bash
composer require andydefer/directive-forge
```

### Dépendances

- `AbstractDirective` - Classe de base des directives
- `DirectiveForgeContext` - Contexte de génération
- `GeneratorService` - Service de génération de fichiers
- `StubVO` - Value Object pour les stubs

## API / Méthodes publiques

### `getSignature(): string`

Retourne la signature de la commande.

**Retourne :** `string` - `'forge:data {name}'`

**Exemple :**
```bash
./directive forge:data user
```

---

### `getDescription(): string`

Retourne la description de la directive.

**Retourne :** `string` - `'Create a new data DTO class'`

---

### `getAliases(): StringTypedCollection`

Retourne les alias de la commande.

| Alias | Description |
|-------|-------------|
| `create-data` | Alternative à `forge:data` |
| `make-dto` | Alternative à `forge:data` |

**Retourne :** `StringTypedCollection` - Collection des alias

---

### `shouldBootLaravel(): bool`

Indique si Laravel doit être booté avant l'exécution.

**Retourne :** `bool` - Toujours `true`

---

### `execute(): ExitCode`

Exécute la directive de création de Data DTO.

**Retourne :** `ExitCode` - Code de sortie

**Exceptions :** 
- `InvalidArgumentException` - Si le nom est invalide
- `Throwable` - Pour toute autre erreur d'exécution

## Flux d'exécution

```
execute()
    ↓
getArgument('name') → $name
    ↓
Vérification : $name n'est pas vide ?
    ├── Non → error('Data name is required') → ExitCode::INVALID_ARGUMENT
    └── Oui → Suite
    ↓
getApplication() → $app
    ↓
$app->make(DirectiveForgeContext::class)
    ↓
setTypeDefinition(new TypeDefinitionRecord('data', 'Data', 'Datas'))
    ↓
$app->make(GeneratorService::class)
    ↓
normalizeFileName($name) → $fileName
    ↓
createFilePath($fileName) → $filePath
    ↓
getFileName() → $className
    ↓
buildNamespace($filePath) → $namespace
    ↓
Vérification : $context->fileExists($fileName) ?
    ├── Oui → error('Data already exists') → ExitCode::INVALID_ARGUMENT
    └── Non → Suite
    ↓
getCustomDataItem('description', 'Data DTO for ' . $name) → $description
    ↓
loadStub('data') → $stub
    ↓
replace('namespace', $namespace)
replace('class', $className)
replace('description', $description)
    ↓
ensureDirectoryExists()
    ↓
GeneratorService::generate($stub, $filePath, $baseDirectory)
    ↓
Vérification : isSuccess() ?
    ├── Oui → info('✅ Data created successfully!') → ExitCode::SUCCESS
    └── Non → error('❌ ' . $message) → ExitCode::FAILURE
```

---

## Gestion des erreurs

| Situation | Exception/Code | Message |
|-----------|----------------|---------|
| Nom de data manquant | `ExitCode::INVALID_ARGUMENT` | `Data name is required` |
| Data déjà existante | `ExitCode::INVALID_ARGUMENT` | `Data already exists: {path}` |
| Caractères invalides dans le nom | `ExitCode::INVALID_ARGUMENT` | `FilePath contains invalid characters` |
| Erreur de génération | `ExitCode::FAILURE` | Message d'erreur du `GeneratorService` |
| Exception inattendue | `ExitCode::FAILURE` | Message de l'exception |

## Intégration

### Avec DirectiveForgeContext

Le contexte fournit :
- La résolution du namespace (`buildNamespace()`)
- La normalisation du nom de fichier (`normalizeFileName()`)
- La création du chemin (`createFilePath()`)
- La vérification d'existence (`fileExists()`)
- Le chargement des stubs (`loadStub()`)

### Avec GeneratorService

Le service de génération :
- Écrit le fichier sur le disque
- Retourne un `GeneratorContext` avec le résultat
- Gère les permissions et les erreurs d'écriture

### Avec AbstractDirective

La classe mère fournit :
- `getArgument()` - Récupération des arguments
- `getCustomDataItem()` - Récupération des tags personnalisés
- `getApplication()` - Accès au conteneur Laravel
- Les méthodes de sortie console (`info()`, `error()`, `line()`)

## Performance

- **Parsing** : O(1) - L'argument est un simple string
- **Génération** : O(1) - Écriture d'un seul fichier
- **Validation** : O(1) - Vérification d'existence du fichier
- **Mémoire** : Minimal - Le stub est chargé en mémoire

## Exemple complet

```bash
#!/bin/bash

# Création d'un Data DTO simple
./directive forge:data user

# Création avec description
./directive forge:data user-profile <description="User profile data transfer object">

# Création dans un sous-dossier
./directive forge:data admin.user-profile

# Création dans un dossier profond
./directive forge:data api.v1.user.create

# Utilisation d'un alias
./directive create-data product

# Utilisation d'un autre alias
./directive make-dto category
```

**Résultat :**
```
✅ Data created successfully!
   Path: /app/Datas/UserData.php
   Class: App\Datas\UserData
   Mode: app
```
